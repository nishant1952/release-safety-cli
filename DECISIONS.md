# Decisions the write-up did not make

One line each. "Spec" means PROMPT.md; "W" means writeup.md.

## Inputs and tooling
- All repo reads go through `git show <sha>:<path>` at the resolved head (or base), never the working tree, so the brief depends only on the range.
- The diff is `git diff --unified=0 --find-renames` over the range; it is checked against data/pr13/pr13.diff in the test.
- Files are bucketed by their immediate directory (`dirname`).
- PR metadata is located by matching the resolved range against `data/*/REFS.txt`; `--pr <file>` overrides. It is a declared input.
- `--ignore-declared` drops every declared input: the PR export, the metrics catalog, and the entry points read from package.json scripts and index.html.
- Dev dependency `@types/bun` is for editor types only; no runtime dependency beyond ts-morph and the Anthropic SDK.

## Gates (W 1a)
- Gate 1 trip blocks the release; gates 2 and 3 trip to a human (W 1a items 2 and 3 say "human"; item 1 says neither, and W 1a's intro says gates "block the release or route it to a human").
- Gate 1 scans every added line with fixed regexes: private keys, AWS/GitHub/Slack/`sk-` tokens, JWTs, credential assignments, URL credentials (secrets); email, SSN, card numbers (PII); absolute http(s) URLs, IPv4 addresses, `localhost:<port>` (hardcoded environment values).
- CI status is read from a `statusCheckRollup` array in the PR export when present (declared); absent means unverifiable, tagged assumed, routed to human (W 2).
- Gate 2 treats as API surface: exported declarations (compared by signature, value ignored), route strings (`path === "/..."`, `.get("/...")`, `<Route path=...>`), and files whose name contains schema, catalog, openapi or swagger (any removed line not re-added is breaking). The metrics catalog counts as an event schema under this rule.
- Gate 3 trips on added raw `UPDATE … SET`/`DELETE FROM`/`TRUNCATE`/`DROP`/`ALTER TABLE … DROP|ALTER COLUMN|RENAME|TYPE`, ORM bulk writes, and removed `CREATE TABLE`/`ADD COLUMN` lines; `CREATE`, `ADD COLUMN` and `INSERT` are additive.
- The gate bypass in W 1a's caveat is not implemented: no PR field marks one in the input.

## Signals
- Reversibility: rules on added lines only. An HTTP call (`fetch`, `axios`, `got`, `ky`, `http(s).request`) counts as an external API client unless its first argument is a same-origin path literal; when unsure it leans irreversible. Telemetry posts to the app's own `/api/...` are internal.
- Feature flag: only `getBooleanValue(key, default)` calls and `@fireweave-controlpoint` anchors count as flags. Each added line is classed control (reads or configures the flag), inside (either branch of a flag conditional/if/&&, or after an `if (!flag) return` guard in a same-file component the flag is passed to as a prop), or outside. Blank, comment and bracket-only lines are not classed; non-TS files (CSS) are outside. Value: none / partial (any outside line) / full.
- Feature flag: "flag exists in production", "both states tested" and "kill path works" (W appendix) need a flag service and tests; they are named as unchecked in the note rather than guessed.
- Path: entry points are files run by a workspace package.json script (`bun|node|tsx|ts-node <file>`) or loaded by a package's index.html `<script src>`. Imports resolve relative paths and workspace package names only; external packages are not followed. "live" means at least one changed file reaches an entry point; per-file chains and unreached files are listed. Inside TSX files, components are followed by JSX usage up to a `<Route element=...>` in the same file. Traces (W appendix) are not available, so callers are static only.
- Path provenance: the import graph and routes are measured from code, but entry points come from package.json/index.html, so the path value is tagged declared; with no entry points it is live, assumed (W 2).
- Reach: calls on added lines outside apps/api are followed through definitions (depth ≤ 4, repo files only) until a `/api/...` literal is found; each endpoint maps to the apps/api handler `path === "<endpoint>"` and the `services.x.y()` calls and imported functions in its block. Org-wide search for topics, tables and cache keys (W appendix) is not done.
- Reach worth: the metrics catalog has no `tier` field at c5da112a. A tier applies when a catalog entry's `source` names a reached call; any non-"low" tier counts as high. With no applicable tier the reach is high, assumed (W 2 "the reach is wide").
- Failure mode: first-match rules on each changed file's path (docs/tests, then security, then infra, then domain); the value is the set over the change. Infra paths include `infrastructure/`, `observability/`, `fireweave/` (the flag harness), CI, Docker, scripts and manifests. CSS and UI components are domain.

## LLM
- Model `claude-opus-5-5`, effort low, structured JSON output, server-side refusal fallback `"default"`; no temperature (rejected by the API). Any API error, refusal or bad JSON makes the LLM signal "unavailable".
- LLM answers are tagged assumed (a model opinion, neither measured nor declared). They are shown beside the rules, never replace them; a code-vs-model disagreement is listed under Disagreements and lowers confidence.
- Detection (per the fast-detection resolution below): metric/log calls on added lines are found through names imported from observability/telemetry/metric/log modules, plus `logger.*`/`console.error|warn`, and classed by name and value: error rate (name has error/fail), latency (name has _ms/duration/latency, or a timing value), value (non-constant, non-timing value) or count. Infra detectors: error-rate or latency calls (measured), deploy health checks (declared; only files the CI workflow executes or loads with `compose -f`, two levels deep, teardown `down` lines skipped), alerts naming an emitted metric (declared). Domain detectors: a value metric or a test importing a changed domain file (measured). Security: an auth-error alert (declared). Slow with only domain missing is tagged measured; any other slow is assumed. Known proxies that can over-credit domain: any test importing a changed domain file, and any non-constant value argument, count as a business-level check.
- Detection cross-check: metric names emitted on changed lines vs names declared in the metrics catalog; any mismatch is a disagreement in the brief (W 2 "Measured beats declared").
- History: non-merge commits before base touching the changed files (lockfiles and generated files skipped). Revert = subject starts with "Revert" or body says "This reverts commit"; fix = subject starts with Fix/Fixes/Fixed/Hotfix (a later "and fix X" clause does not count). Thin = shallow clone, < 5 such commits, or repo history before base spanning < 7 days; thin history is "history unavailable", tagged assumed so it lowers confidence (W 2). No RCA store or incident tracker is available.
- Provenance: agent `Co-authored-by` trailers in the range's commits are measured; "Made with X" in the PR body or a bot PR author is declared. Whether a human was in the loop is not claimed: the input cannot show it.
- Test coverage: a test file "covers" a changed code file when it imports it by a relative path. For agent-assisted changes only tests that existed at base count (W 1d); for human changes all covering tests count.
- Measured confidence: low if no counted test covers any changed code file, one step lower if some lack one, one step lower if a human author has no earlier commit on a touched file (multi-author repos only). Review depth is unavailable (no review data in the PR export); the LLM coherence read may only lower confidence.
- Missing-data policy lives in src/policy.json with section 2's rules verbatim. "The data is touched" is recorded as not applied: data writes come from the diff, which is always present. Only missing inputs lower confidence (an LLM answer that came back does not); each disagreement lowers it one step. The measured-only level is kept apart and is the only one that can move the mode.

## Write-up contradictions, resolved in code (writeup.md is frozen)
- Undo speed. Section 3, line 106: "Without one, undo is a rollback or redeploy and a slice is a canary or percentage deploy, which is why such changes sit in the slow column." Section 3, example row 1: "Adding logs for more visibility | Infra | Low | Fast (revert or flag) | ... | Auto". Resolution: undo speed is measured, not categorical. A flag covering the whole change is fast. Otherwise time to revert (1c signal 6) decides: one-click rollback or a measured pipeline under 15 minutes is fast; longer is slow; unknown rounds to slow (W 2). Edits outside the flag use the revert path. Line 106 overstates: it should read "usually slow unless time to revert is measured fast".
- Fast detection. Appendix rank 3 defines detection as "Whether the changed path emits anything an alert watches", while its ignore case says "Auto mode needs only the deploy health check". Resolution: detection is fast when a detector matching the failure mode exists on the changed path: infra -> deploy health check, error rate or latency (metric calls in the diff, or deploy config); domain -> a business-level check, a metric or test that asserts the value (W 4.3); security -> an auth-error alert. Mixed failure modes need a detector for each. Missing or unknown rounds to slow (W 2). The ignore case "Auto mode needs only the deploy health check" is the infra branch of this rule, not a separate rule.
- Time to revert (1c signal 6, per the undo-speed resolution): a workflow that names a rollback (in a `name:` value or a key) or a `workflow_dispatch` input named ref/sha/version/tag/commit is a one-click rollback (declared). CI run history is not an input, so a measured pipeline duration is never available here; a job `timeout-minutes` is shown as a declared bound but not counted as a measurement. Otherwise "full build and deploy", assumed (W 2).

## Decision engine (W 3)
- Damage is high only when the path is live and the reach is high; a change nothing reaches, or one that reaches only low-worth systems, is low damage.
- Window is short only when the change is reversible, undo is fast and detection is fast (per the two resolutions above).
- Probability shift: one step toward caution when the measured confidence is low; assumed inputs never trigger it (W 2). It is capped at Human: Block comes only from a gate.
- LLM: a coherence mismatch adds at most one step toward caution; it never lowers the mode and never touches gates, grid placement or the plan.
- Flag advice (W 3 line 106): when the grid with a full flag would be lower, the brief says adding the flag (or moving outside edits behind it) is the cheapest way left.
